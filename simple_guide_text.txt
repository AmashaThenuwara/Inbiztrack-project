1. Is the first project too complex?
For this assessment, yes. The first guide is a good product idea, but it adds a dashboard, live search,
filters, bulk actions, many extra columns and reusable components. The PDF asks for none of those. More
code means more places for a bug, more to explain in an interview, and more time before the deadline.
Recommendation: submit this simple version. A small app that works perfectly, validates input,
enforces the delete rule and has tests will score better than a large app with one broken feature.

3. Setup
Install PHP 8.3+ (8.2 works with Laravel 12), Composer, Node.js 20+, MySQL, Git and VS Code. Enable the
PHP extensions pdo_mysql, mbstring, openssl, fileinfo and pdo_sqlite (used by the tests).
3.1 Create the project
composer create-project laravel/laravel inbiztrack
cd inbiztrack
composer require livewire/livewire:^3.8
npm install
Why Livewire 3.8?
Livewire 4 exists but generates different files. Pinning ^3.8 keeps your files identical to this guide, and it
supports Laravel 11, 12 and 13.
3.2 Create the database and edit `.env`
CREATE DATABASE inbiztrack CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
Fresh Laravel defaults to SQLite, so switch these lines in .env to MySQL:
APP_NAME=InBizTrack
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=inbiztrack
DB_USERNAME=root
DB_PASSWORD=
Then run php artisan config:clear. A fresh Laravel app already includes Tailwind CSS and Vite; nothing
else to install.
3.3 Run during development
Use two terminals:
# terminal 1
php artisan serve
# terminal 2
npm run dev

database/migrations/xxxx_create_tasks_table.php
<?php
use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;
return new class extends Migration
{
    public function up(): void
    {
        Schema::create('tasks', function (Blueprint $table) {
            $table->id();
            // Deleting a project also deletes its tasks
            $table->foreignId('project_id')->constrained()->cascadeOnDelete();
            $table->string('title');
            $table->boolean('is_completed')->default(false);
            $table->timestamps();
        });
    }
    public function down(): void
    {
        Schema::dropIfExists('tasks');
    }
};

foreignId('project_id')->constrained()->cascadeOnDelete() creates the foreign key; deleting a project
makes MySQL delete its tasks.

app/Models/Project.php
<?php
namespace App\Models;
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\HasMany;
class Project extends Model
{
    use HasFactory;
    protected $fillable = ['name', 'description'];
    public function tasks(): HasMany
    {
        return $this->hasMany(Task::class);
    }
    // Used by the delete rule
    public function incompleteTasksCount(): int
    {
        return $this->tasks()->where('is_completed', false)->count();
    }
}
app/Models/Task.php
<?php
namespace App\Models;
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\BelongsTo;
class Task extends Model
{
    use HasFactory;
    protected $fillable = ['project_id', 'title', 'is_completed'];
    protected function casts(): array
    {
        return ['is_completed' => 'boolean'];
    }
    public function project(): BelongsTo
    {
        return $this->belongsTo(Project::class);
    }
}
hasMany / belongsTo define the one-to-many relationship. $fillable whitelists columns for mass assignment.
incompleteTasksCount() is the single place that defines the delete rule.

app/Livewire/Projects/Index.php
<?php
namespace App\Livewire\Projects;
use App\Models\Project;
use Livewire\Component;
class Index extends Component
{
    public string $name = '';
    public string $description = '';
    public ?int $editingId = null;
    public ?string $successMessage = null;
    public ?string $errorMessage = null;
    protected function rules(): array
    {
        return [
            'name' => ['required', 'string', 'max:255'],
            'description' => ['nullable', 'string', 'max:5000'],
        ];
    }
    protected function messages(): array
    {
        return ['name.required' => 'Please enter a project name.'];
    }
    // Create a new project, or update the one being edited
    public function save(): void
    {
        $this->reset('successMessage', 'errorMessage');
        $data = $this->validate();
        $data['description'] = $data['description'] ?: null; // '' -> NULL
        if ($this->editingId) {
            Project::findOrFail($this->editingId)->update($data);
            $this->successMessage = 'Project updated.';
        } else {
            Project::create($data);
            $this->successMessage = 'Project created.';
        }
        $this->resetForm();
    }
    public function editProject(int $id): void
    {
        $project = Project::findOrFail($id);
        $this->editingId = $project->id;
        $this->name = $project->name;
        $this->description = $project->description ?? '';
        $this->reset('successMessage', 'errorMessage');
        $this->resetValidation();
    }
    // Business rule: a project with incomplete tasks cannot be deleted
    public function deleteProject(int $id): void
    {
        $this->reset('successMessage', 'errorMessage');
        $project = Project::findOrFail($id);
        $pending = $project->incompleteTasksCount();
        if ($pending > 0) {
            $this->errorMessage = 'Cannot delete project: '
                . ($pending === 1

How it works
•
save() validates, then updates (if $editingId is set) or creates. One form handles both.
•
deleteProject() counts incomplete tasks. If there are any, it shows the error and returns without
deleting. Otherwise it deletes the project and the foreign key removes its tasks.
•
withCount loads task counts in the same query as the projects (no N+1 problem).
•
wire:key gives each list item a stable identity so Livewire updates the correct element.

app/Livewire/Projects/Show.php
<?php
namespace App\Livewire\Projects;
use App\Models\Project;
use Livewire\Attributes\Locked;
use Livewire\Component;
class Show extends Component
{
    public Project $project;
    public string $newTitle = '';
    #[Locked]
    public ?int $editingTaskId = null;
    public string $editingTitle = '';
    public function mount(Project $project): void
    {
        $this->project = $project;
    }
    public function addTask(): void
    {
        $this->validate(
            ['newTitle' => ['required', 'string', 'max:255']],
            ['newTitle.required' => 'Task title cannot be empty.']
        );
        // Created through the relationship: project_id is set automatically
        $this->project->tasks()->create(['title' => trim($this->newTitle)]);
        $this->reset('newTitle');
    }
    public function toggleTask(int $taskId): void
    {
        // Only tasks of THIS project can be found
        $task = $this->project->tasks()->findOrFail($taskId);
        $task->update(['is_completed' => ! $task->is_completed]);
    }
    public function startEditing(int $taskId): void
    {
        $task = $this->project->tasks()->findOrFail($taskId);
        $this->editingTaskId = $task->id;
        $this->editingTitle = $task->title;
        $this->resetValidation();
    }
    public function saveTitle(): void
    {
        if ($this->editingTaskId === null) {
            return;
        }
        $this->validate(
            ['editingTitle' => ['required', 'string', 'max:255']],
            ['editingTitle.required' => 'Task title cannot be empty.']
        );
        $this->project->tasks()
            ->findOrFail($this->editingTaskId)
            ->update(['title' => trim($this->editingTitle)]);
        $this->cancelEditing();
    }

•

with $editingTaskId.

RefreshDatabase wipes the database the tests use. In phpunit.xml, make sure these two lines are active
(not commented) so tests run on in-memory SQLite and never touch your MySQL data:
<env name="DB_CONNECTION" value="sqlite"/>
<env name="DB_DATABASE" value=":memory:"/>

# InBizTrack - Project Management for a Software Company
Laravel + Livewire app to manage projects and their tasks (assessment submission).
## Features
- Create, list, edit and delete projects ("3/5 Tasks Completed")
- A project with incomplete tasks cannot be deleted (clear error message)
- Live tasks: add, edit title, checkbox complete (strikethrough), delete
- Validation, migrations, seeder, feature tests
## Setup
1. composer install
2. cp .env.example .env && php artisan key:generate
3. Create MySQL database "inbiztrack" and set DB_* in .env
4. php artisan migrate --seed
5. npm install && npm run dev   (second terminal)
6. php artisan serve
## Tests
php artisan test
10.2 Likely interview questions
Walk me through the project.
A project manager creates software projects and adds tasks. Tasks are ticked off live with Livewire. A
project with unfinished tasks cannot be deleted. Laravel handles data and rules, Livewire the reactive UI,
Tailwind the styling.
Explain the relationship between projects and tasks.
One-to-many: a project hasMany tasks and each task belongsTo a project through project_id, a foreign
key.
How do you stop deleting a project with incomplete tasks?
deleteProject() calls incompleteTasksCount(). If it is above zero, it sets the error message and returns
before delete(). Tests cover all three cases.
What does cascadeOnDelete() do?
It adds ON DELETE CASCADE to the foreign key, so MySQL removes a project's tasks when the project is
deleted.
How does the checkbox update without a reload?
wire:click makes Livewire call toggleTask() over AJAX. The method saves the change, the view
re-renders, and Livewire patches only the changed HTML. Blade adds line-through from is_completed.

What is the N+1 problem?
Counting tasks per project in a loop runs one extra query per project. withCount gets the counts in the
same query.
Is it secure?
Livewire adds CSRF protection, Blade escapes output, Eloquent uses bound parameters, $fillable limits
mass assignment, input is validated on the server, and task queries go through the project so tampered
ids return 404. Not covered: authentication.
What would you add with more time?
Login with per-user projects, pagination, search, due dates and priorities, and CI that runs the tests.
Why Livewire?
The brief requires it. It lets PHP developers build reactive pages without writing a separate JavaScript
front end.
Did you use AI?
Answer honestly. If you did: "I used it as a learning aid, then read, tested and understood every part." Be
ready to change any line live, for example the error message or adding a field.
